★★★★★ **THE DISPATCH NAMES THE WRONG REGISTER, FOUR TIMES.** §1.2, §4B, §6 and AC-4 say **`$FFA5`**
for slot 4. **Slot 4 is `$FFA4`**; `$FFA5` is **slot 5, the priority slice**, which P6.92's own
census shows **live during the composite** (17,204 r / 36,651 w). ★★★★ **Building as written would
have mapped the cache over the priority plane mid-blit — P6.78 exactly.** Built against `$FFA4`.

★★★★★ **TWO REAL DEFECTS WERE FOUND AND FIXED DURING THE TASK, AND BOTH ARE THE SAME CLASS:**
1. ★★★★★ **The end-of-run sweep read the cache as game data.** `res-checksum` reported **1 mismatch
   where HEAD had 0** — `type 0 index 0 at $7CD9 len 8999, expected $0BF7 got $98D5`. **`$7CD9 +
   8999 = $A000`: LOGIC 0 straddles slots 3 and 4**, and the sweep walks the arena *directly*, so it
   was the one reader that could run with slot 4 borrowed. ★★★ Nothing was corrupted — the checksum
   read the wrong **aperture**. Fixed by restoring slot 4 before the sweep; **0 mismatches now.**
2. ★★★★★ **`ph_blk_slot4` is declared inside `ifdef PHASE_TEXT`**, and the plain `p3b` gate arm has
   cels and no text window. ★★★★★ **The assembler is what saved it**: had the symbol merely existed
   and been zero, `phase_cache_out` would have mapped **block 0 — the live priority plane** — over
   the arena. **Silent, plausible, P6.78 again.**

> ★★★★★ **And the lesson behind both is one sentence: P6.92 measured slot 4 silent during the draw
> phase ON A BUILD WITH NO RESOURCE CHECKER IN IT. Turning on `-CelCheck` ADDED a draw-phase arena
> reader the census never saw.** ★★★★ **"Silence" was a property of the build measured, not of the
> program** — which is P6.92 §7's own uncertainty flag 2, firing one task after it was written.

★★★★ **So the guard it asked for was built.** `-CachePoison` maps a block that is neither the arena
nor the cache into the borrowed slot: **with the cache off the planes are IDENTICAL** (nothing reads
the aperture — a demonstration, not a measurement-of-one-run) and **with the cache on they DIFFER**
(the guard can fire).

### 3 — Reasoning

**§3(2) — every writer of the slot registers, by literal and by symbol.**

```
mmu_phase.s:51-54   MMU_SLOT3 $FFA3 · MMU_SLOT4 $FFA4 · MMU_SLOT5 $FFA5 · MMU_SLOT6 $FFA6
mmu_phase.s         sta MMU_SLOT5 (phase_slot5) · sta MMU_SLOT3/4 x2 (phase_text_in/out)
sys.s:233-237       sta $FFA3/$FFA4/$FFA5   -- BOOT ONLY, the all-RAM transition (SHARED)
input_probe.s:79-81 sta $FFA4/$FFA5         -- a harness probe, allowlisted by filename [§2N]
```

★★★★ **`mmu_phase.s` is the sole engine owner**, which is why the borrow was written **there** and
not at the call site. ★★★ Adding it at the call site would have created a second writer — §6's
first trigger, and what P6.82 cost a task to undo.

**§3(3) — what holds slot 4 in each phase, and what already touches it.** ★★★★★ **The borrow
mechanism already existed**: `phase_text_in` borrows slots 3 **and 4** for the text window and
`phase_text_out` restores them from `ph_blk_slot3`/`ph_blk_slot4`. ★★★ **That is in the VM phase
(`vm_text_ops.s`, a print opcode); the cache's borrow is in the DRAW phase. Disjoint** [§1.2(4)].
★★ Outside those two windows slots 3 and 4 hold `$3B`/`$3C` for the whole run.

**§4B — what the restore writes, and where the value comes from.** **`ph_blk_slot4` = `$3C`.** Its
provenance is the boot map: `p3b_run.lua` pre-sets all eight slots to `$38+i`, so slot 4 is `$3C`,
and `p3b_probe.s` stores that at init. ★★★ **The register is write-only, so this byte is the only
record** — a read-back returns nothing and a saved copy would be a second opinion about the same
fact [§2F]. ★★ It is the same byte `phase_text_out` has used since T-P0-093.

**§3(4) — a loop's size.** Room 1's three loops are 1,152 / 2,100 / 754 B = 4,006 B; the block is
8,192. Corpus mean is 372 B/cel, so a 9-cel loop averages ~3.3 KB. **The cache degrades rather than
overflows**: a cel that does not fit triggers one flush-and-retry, then **bypasses** and decodes
exactly as before. Both are counted.

**Authority tier.** Every figure is measured in this tree. The cache's shape follows the oracle's
(`unpackViewCelData` decodes once and keeps the bytes) — ★ **believed original, not a ScummVM
normalisation**, since it is a host-side memory choice with no observable behaviour.

**§2H's three checks.** (1) *A second mechanism for a different object class?* Yes — P6.88's skip
handles **unchanged** sprites and the cache handles **re-decoded** ones; they compose, which is why
standing gains 16.6% on top of a path P6.88 already shortened. (2) *The calling routine.*
`vc_decode_row` is called from `cp_composite`'s row loop, so the cache's lifetime is the **draw
phase** — that is why the borrow is at `phase_draw_enter`, not around the decode. (3) *Grep the
reports.* P6.74, P6.78 (stale slot records), P6.82 (one owner), P6.83 (VIEW read in place), P6.92
(the census) all agree; **and P6.92's uncertainty flag 2 predicted this task's first defect.**

**§2S.** No sibling claim is made.

### 6 — Reactive deviations and route accounting

1. ★★★★★ **The register correction** — `$FFA4`, not the dispatch's `$FFA5`. §1.
2. ★★★★★ **§6's third trigger fired mid-task** (`logic_copy_diff`-class non-zero) and **I stopped
   and reported rather than repairing.** ★★★★ **Jay then said "make the fix"**, so both halves were
   taken: the sweep's restore, and `-CachePoison` as the guard for the class.
3. ★★★★ **Per-cel bump allocation, not per-loop LRU with three entries** — a §22.5 deviation. A
   per-loop entry must know a loop's total size before admitting its first cel, which means parsing
   every cel header of that loop up front; per-cel needs only the `w*h` `vc_decode_begin` already
   produced. ★★★ **Identical for the measured workload** (20 cels = 4,006 B in 8,192, nothing ever
   evicted) and **the difference shows only in AC-2's warm-up: 21 first-touch misses against 3.**
4. ★★★ **`-CelCheck -NoCelCache` stood in for AC-6's `logic_copy_diff` run**, because `-ResCheck`
   carries `-DP3B_NO_CEL` by construction and `-CelCheck` + cache exceeds region A. ★★ It tests the
   borrow and restore, which is what §1.2(2) is about.
5. ★★ **A `$CelLink` ordering bug in my own tooling**: the FLAGS line used `$CelLink`, which is
   computed ~140 lines below it and below the lwasm call, so **both branches were false and the
   cache was silently not built.** ★★★ **Loud only because the symbols then went missing — had the
   cache had no symbols it would have measured as "the cache buys nothing".** Fixed by spelling the
   condition from `$FLAGS`, which is the file's own stated rule.
