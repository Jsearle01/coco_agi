### 3 — Reasoning

**3.1 ★★ POP's `build.bat` did not run, and it is a pre-existing condition I did not cause.**
cmd.exe produced `'vel'`, `'RROR:'`, `'orlevel'` — word fragments. Byte counts: **23 CRLF pairs
against 900 lone LFs**. `.gitattributes` pins `*.bat text eol=crlf` precisely because *"cmd.exe
cannot parse an LF-only .bat file"*, and git reported `i/lf w/mixed attr/text eol=crlf`. So the
committed blob was correct and the **working-tree checkout** was not.

Verified content-identical to `HEAD` ignoring EOL **before** touching it, then restored by
delete-and-re-checkout: CRLF-clean, content unchanged, `git status` clean. ★ This is not a
content change and nothing was committed in POP. Without it §2 step 2 was impossible.
★ My first `grep -c $'\r'` said "923 CRLF lines" and was misleading; the byte-level count is what
settled it.

**3.2 ★★★ The blocker, with the mechanism named rather than inferred (L-32).**
`GFX_MODE_ENTSZ = 7`. A third row grows `gfx_mode_table` by 7 bytes and **shifts everything after
it** in every image linking the HAL. POP defines `HAL_GFX_MODE_SERVICE`, so POP assembles the
table. Evidence, not proximity: in POP's `loader.map` after the change, `gfx_mode_table` sits at
`$7B65` with `gfx_pal4` **21 bytes later — three 7-byte rows** where the baseline had two.

Result: **27 POP artifacts changed**, every one a binary that links the HAL, each exactly +7:
`loader.bin` 1606→1613, `intro_splash.bin` 28145→28152, `tile_probe.bin` 1500→1507,
`loop_probe.bin` 1269→1276, and `probe.dmk` rehashed. Full table in §5.

★ **This is not §8.4's case.** The row *can* be added without editing mode 1 — mode 1's emitted
bytes are unchanged (§5) — so the descriptor layout is not the constraint. The constraint is that
**POP's shipped binaries embed the table**, so any addition to it is an artifact change for POP.

**3.3 ★★ The `ifdef` fallback works, and Karateka proves it (AC-2/AC-7).**
The guard is **structural, not something I added**: `gfx.s`'s table (line 774) and `GFX_MODE_MAX`
(347) already lie inside `ifdef HAL_GFX_MODE_SERVICE` (76…842). With the service undefined both
additions vanish. The only unguarded addition is `hal.inc`'s `GFX_MODE_320x200x16 equ 2`, a bare
`equ` that emits nothing. **Karateka, which never defines the service, rebuilt 104/104
byte-identical** — that is L-27 satisfied by removal rather than by argument: the definition is
genuinely absent in a real tree and it still builds, unchanged.

**3.4 The VRES value — two independent sources, not derived (§5, §8.5 not triggered).**
`[ref: GIME-RM — $FF99 VRES (Video Resolution Register) bit layout]` gives
`LPF1 LPF0 / Visible lines: 0 0 = 192, 0 1 = 200, 1 0 = Reserved, 1 1 = 225`.
`[ref: docs/ground-truth/SockmasterGime.md:110-113]` gives `Bits 6-5 LPF 00=192 / 01=200 /
11=225`. Both agree: **LPF = 01 → 200 lines**, so `$FF99 = %0 01 111 10 = $3E`, differing from
mode 1's `$1E` in the LPF field alone. ★ No `[no-ref:]` marker is needed — the documents settle it.
★ The GIME manual is a real text PDF (2,523 text operators, no images); the quoted table was
extracted, not paraphrased. Per §2.2 this citation is executor-verifiable and
orchestrator-unverifiable, which is why the quoted text is reproduced here.

**3.5 Mode 2's geometry.** 160 B/row × 200 rows = **32,000 B = $7D00**, `$3E80` = 16,000 words.
Blocks: 32,000/8192 = **3.91 → 4**, against mode 1's 30,720/8192 = 3.75 → 4. ★ **Confirmed: 200
lines costs zero additional MMU blocks**, 768 B spare in the last block.

**3.6 §2S — refs and scopes.** Everything above measured at the refs in the grep block. Siblings
were modified only in the two HAL files and only transiently; both are back at their receipt
state, verified by rebuild. `coco_agi` is **not** in `SIBLINGS`, so its divergent `gfx.s` cannot
block any build — §2's sequencing hazard is not armed.
