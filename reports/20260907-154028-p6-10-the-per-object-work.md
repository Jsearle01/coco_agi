### 3 — Reasoning

**Authority tier.** Everything below rests on **measurement of our own port** — tier 2-equivalent
in the sense that it is dynamic observation rather than a reading of ScummVM or the Specs. No
claim here is sourced from the oracle, so §2.1's original-vs-normalisation distinction does not
arise. The one structural claim about AGI itself — that a game's objects are low-numbered — is
**not asserted from the Specs; it is measured**, by the nine-title gate staying byte-identical at
`VM_OBJ_SCAN=16`.

#### 3.1 §2H's three checks

1. **Is there a SECOND mechanism serving a different object class?** ★★★★ **Yes, and it is the
   finding.** The dispatch's framing has one mechanism — per-object work. There are two: a
   **per-slot traversal** (constant, 255 iterations, independent of objects) and a **per-active
   body**. They are additive and they behave completely differently, and a per-cycle total cannot
   separate them — which is exactly L-10.
2. **Name the routine that CALLS it.** Both are called from `vm_interpret_cycle`
   (`vm_cycle.s:194` and `:273`), unconditionally, once per cycle, with no guard on whether any
   object is active. **The caller is what makes the traversal unavoidable**: there is no "are
   there any objects?" test anywhere above them.
3. **Grep the reports for the same subsystem before citing a prior characterisation.** P6.9's
   `0.07067 s` / `0.37547 s` are the figures this dispatch is built on. They come from p3b, and
   §7.1 records that p3b's timing builds are missing `PIC_NOCOUNT`. ★★ **I did not re-derive them
   and I do not rely on them**: every number in this report comes from arms measured this task.

#### 3.2 Why the ablation is a bound and not an `ifdef` round the calls

Skipping either call outright stops objects moving and updating, so a later cycle interprets
different bytecode and the arm has moved several variables at once — **L-73's shape exactly**.
Lowering the scan bound moves one thing: how many EMPTY slots are walked.

★★★★★ **And it is self-checking.** If the bound cut a live object the 288-byte state diff would
move. It does not: **9/9 byte-identical at `VM_OBJ_SCAN=16`.** So the ablation is *proved*
behaviour-neutral rather than assumed to be, and the time delta is the traversal and nothing else.
**`opcount` is identical between paired arms in all four rooms** (2950/2950, 3174/3174, 3179/3179,
2138/2138) — L-79's requirement that the arms be shown to have run the same program.

#### 3.3 What the numbers say

Per-slot cost **74.0 CPU cycles**. ★ My own hand-arithmetic beforehand said ~35 from an instruction
count, and it was wrong by 2×; **it is labelled unverified here because it was, and it is recorded
only to note that computing it would have been a mistake** (§8).

#### 3.4 §2S — ref and scope of the sibling claim

The only sibling claim is §0's baseline citation, at POP `104b197` / Karateka `29f8f0a`, both `wip`,
scope = HEAD and working-tree cleanliness. No sibling artifact was built or compared.

**7.2 ★★★ AC-3's curve is confounded and I could not decouple it.** Rooms differ in object count,

**7.4 ★★ The sweep's VOID guards are asymmetrically tested.** The room-jump guard's *condition* was

non-zero exit is noise in a harness where exit codes matter, and it should be separated.
