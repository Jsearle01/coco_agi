### 7 — Uncertainty flags

#### 7.1 ★★★★★ For Jay — the arrows
Your two runs of the new build never moved Graham; the old build took 3-4 taps. **Both builds do
the same thing with the same key-down per cycle**: I pressed LEFT for exactly one cycle, three
times, in both, and got the same three steps and the same freeze at x=107, every cycle identical.
**The difference is the finger, and the code punishes the finger.** The port reads the arrow once
per cycle as a LEVEL: a tap between two reads is lost, and a tap across two reads is "left, left",
which AGI reads as start, then stop. Only a tap caught by exactly one read moves him. **Faster
cycles change which taps land where.** They will keep making this worse until `p3_poll_dir` takes
EDGES, as the oracle does [keyboard.cpp:226-242]. **That fix should come before more speed.**
