### 1 — Summary
★★★★★ **Key delivery was never broken. My P6.23 diagnosis was wrong.** The probe was spinning at
`ip_wait`: it clears `IP_GO` in its own initialisation — correctly, because `$0020` is direct page
and DECB was there — and the host set `GO` in the same frame as the PC, so the guest erased it.
**Every symptom followed: `NRAW=0`, `NKEY=0`, and every byte of `HAL_key_scan`'s state still at its
assembler initialiser.** `natkeyboard:post('a')` reaches the matrix in **0.050 s**, and every
ioport field lands exactly where `hal_globals.s`'s table says. With the handshake fixed:
**AD-134's scheme decodes 10 of 10**, and **a typed line reaches the parser** (`egon=2`). The idle
poll cost 896 cycles — **6% of a frame, every frame, and the input line does not block** — so an
all-columns pre-test now answers "is anyone typing" in **75 cycles, 0.50%**, a 12× reduction that is
exact rather than approximate. AC-1 is **not** reached.

### 3 — Reasoning

**A. Where P6.23 went wrong, stated plainly.** [authority: measurement]
P6.23 reported *"the guest IS strobing — `$FF02=$EF` observed"* and concluded delivery was at
fault. **`$FF02=$EF` was a value DECB left behind.** The guest had not executed a single scan: this
task's re-run reads `$FF02=$FF`, and the guest's own `hal_kb_col`, `hal_kb_idx`, `hal_kb_rows` and
`hal_kb_mod` all read their assembler initialisers. ★★★★ **A reading consistent with several causes
is not a diagnosis** [L-97], and I treated one as confirmation because it agreed with the
hypothesis I already had.

★★★ **The instrument that should have caught it did not, and that is the sharper finding.**
`IP_NRAW` was added specifically to separate "the matrix saw nothing" from "the decoder resolved
nothing" — and I incremented it **after** `HAL_key_scan` returns a key, downstream of both. It now
counts raw pressure from `hal_kb_idx`, before any table lookup. **A discriminator placed downstream
of the thing it discriminates is not one** [§2W].

**B. The delivery chain, walked one layer at a time.** [`keymatrix_check.lua`]
The host asserts CR data mode, drives one column low and reads the rows — the same two instructions
`HAL_key_scan` uses, with no 6809 involved:

```
=== ioport: 96 fields across 32 ports ===
=== baseline (no key): 0 row/col hits ===
=== natkeyboard:post('a') -- empty now false ===
  ★ post REACHED the matrix after 0.050 s: row0/col1
  ENTER ★ row6/col0    CTRL ★ row6/col4    ALT ★ row6/col3
  UP ★ row3/col3   DOWN ★ row3/col4   LEFT ★ row3/col5   RIGHT ★ row3/col6
  SPACE ★ row3/col7   0 ★ row4/col0
```

★★★★★ **Every position matches `hal_globals.s`'s table**, which is an independent confirmation of
the matrix transcription against MAME's own ports — the thing P6.22 flagged as unvalidated.

**C. Then the guest and host on the same frame.** With delivery established, `input_gate.lua` scans
host-side each frame and prints the guest's state beside it:

```
HOST sees col4=02 | guest NRAW=0 NKEY=0 rows=$00 idx=$FF mod=$00 col=0 | CRA=$34 CRB=$B4
```

★★★★ **Every guest byte is its static initialiser.** `hal_kb_col=0` after a completed scan is
impossible (the loop leaves it at 8), so the scan had never run — and the PC resolved to
**`ip_wait+2`**, the GO spin. §1's handshake race.

**D. AC-5, and the fix is exact rather than a trade.** [measurement]
896 cycles per idle scan, **6.0% of a 14,915-cycle frame**, paid every frame because the input line
does not block. `HAL_input_poll` already answers "is any key down" by driving all eight columns at
once; the same four instructions inline give a 12× reduction. ★★★ **It cannot change the return
value: if no row is low with every column selected, no row can be low with one selected** — the
same closure argument as text.s's 16-bit checksum.

**E. §2M: nothing shared moved.** The decoder and the early-out are in `hal_globals.s`, which
`hal_sync_check.py`'s own `PROJECT_LOCAL` mapping names for all three repos. `input.s` is
byte-unchanged. **POP and Karateka were not rebuilt because their inputs did not change** — the
stronger property, and `hal_sync` is green in all three.

**F. §2S refs.** POP `104b197`, Karateka `29f8f0a`, measured this task. ScummVM at the pin
`9d9b9e93`.
